Check now runs live web searches against the organiser sites and reports anything that has moved. Look for new events sweeps the industry directories. Both cost API credit, so use them when you need an answer rather than out of habit — the scheduled Monday run covers routine drift.

How updating works on this deployment
  • Scheduled. A GitHub Actions workflow runs every Monday at 07:00 UTC, re-checks the priority events, sweeps for new ones, and writes data/verification.json. If anything looks different it opens a pull request instead of editing the register. Merging it triggers a Vercel deploy.
  • On demand. The buttons above call /api/refresh, a serverless function that holds the API key server-side. Results show for this session only; they are not saved. Anything worth keeping goes into data/events.json by hand.
  • Why there is a human gate. Organisers publish inconsistent dates and the checker will sometimes treat an aggregator listing as authoritative. Three entries in this register already disagree across sources. Nothing should silently overwrite a date somebody might book travel against.
